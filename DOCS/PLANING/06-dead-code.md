# 06 — ניקוי קוד מת

> 🟢 **קל.** אין סיכון תפעולי, אבל יש כאן מלכודת אמיתית למי שיתחזק את הקוד.

## 1. `src/components/Events/EventDetails.tsx` — 329 שורות שאף אחד לא מריץ

הקומפוננטה **לא מיובאת בשום מקום**. בדיקה:

```bash
grep -rn "EventDetails" src/ --include=*.tsx | grep -v "src/components/Events/EventDetails.tsx"
```

כל התוצאות מתייחסות ל**טיפוס** `EventDetails` או למשתנים בשם `eventDetails` — אף אחת לא מייבאת את הקומפוננטה. מסלול התצוגה בפועל הוא `src/pages/EventPage.tsx`.

### למה זה מסוכן ולא רק מיותר

הקובץ מכיל לוגיקת קיבוץ פריטים לקטגוריות שנראית **טובה יותר** מזו שבפועל בשימוש:

```js
// EventDetails.tsx — קוד מת
eventMenuItems.forEach(item => {
  if (acc[item.category]) {
    acc[item.category].push(item);
  } else {
    acc['other'].push(item);   // ← fallback מפורש לפריטים יתומים
  }
});
```

זו מלכודת קלאסית: מפתח שיחפש את לוגיקת הקטגוריות ימצא את הקובץ הזה, יסיק שהוא המקור, ויתקן בו באג — בקוד שלא רץ. בדיוק הבלבול הזה האט את האבחון של באג הקטגוריות ב-23/08.

### מה לעשות

**לפני המחיקה** — לבדוק אם ה-fallback הזה שווה להעביר ל-`EventPage.tsx`. ב-`EventPage` פריטים יתומים אמנם מוצגים בתצוגת "הכל", אבל מאבדים את שם הקטגוריה ואי אפשר לסנן אליהם. הגישה של `EventDetails` — לזרוק אותם לדלי `other` — עשויה להיות התנהגות עדיפה.

זו החלטת מוצר, לא רק ניקיון. להחליט קודם, למחוק אחר כך.

```bash
git rm src/components/Events/EventDetails.tsx
```

## נוסף 24/08/2026 — עוד שני מסכים מתים, ובתוכם חישוב שמטעה

נמצא בסקירה החוזרת של קמפיין המבקרים האנונימיים. **מתועד ולא נמחק.**

**`src/components/Events/EventDetails.tsx`** — רכיב מסך אירוע שלם. השם `EventDetails`
אכן מופיע בכמה קבצים, **אבל תמיד כטיפוס נתונים מתוך `src/types`, ולא פעם אחת
כרכיב.** לרכיב עצמו אין מייבא.

**`src/components/Events/UserInfoModal.tsx`** — חלון "פרטי המשתמש", שמבקש שם,
**טלפון ואימייל**. המייבא היחיד שלו הוא `EventDetails.tsx` שלמעלה, ולכן הוא מת
בשרשור.

**ושתי נקודות שחשוב לרשום לצידם:**

**1. החלון המת שומר רק לזיכרון הדפדפן.** בדקנו במפורש אם הוא כותב טלפון ואימייל
לפרופיל שבמסד — **הוא לא.** כל מה שהוא נוגע בו הוא אחסון מקומי. כלומר אין דרך
נסתרת שבה פרופיל אנונימי מקבל פרטי קשר, וזה מאשש את הממצא ב-[26](26-anonymous-visitors-leave-empty-profiles.md)
שהפרופילים באמת ריקים.

**2. וזו הנקודה המסוכנת — שני המסכים המתים מחזיקים חישוב "האירוע נגמר" שונה
מזה שרץ בפועל.** הם משתמשים בחישוב שסוגר את החלון בחצות של יום האירוע, בעוד
**עמוד האירוע החי סוגר אותו שש שעות אחרי שעת ההתחלה.** מי שיקרא את הקוד המת כדי
לענות על שאלה משפטית — כמה זמן יש למשתתף לבטל את שיבוצו — **יקבל תשובה שגויה
ומקלה.** זה קרה בפועל בסקירה הזו ותוקן; הפירוט ב-[12](12-legal-documents.md)
וב-[41](41-anonymous-data-never-expires.md).

**כלומר יש כאן קטגוריה שלישית שלא הייתה ברשומה הזו קודם:** לא "אין מייבא"
