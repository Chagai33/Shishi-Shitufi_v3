# בדיקות חוקי מסד הנתונים

הבדיקות היחידות בפרויקט. הן בודקות את `database.rules.json` מול האמולטור של
Firebase, ואינן נוגעות בפרודקשן, בקוד המוצר או בבניית הפרונטאנד.

## דרישה מקדימה — JDK 21

האמולטור של Realtime Database רץ על Java, וכלי השורה של Firebase דורש
**JDK 21 ומעלה**. גרסאות ישנות יותר נדחות עם הודעה מפורשת.

לבדיקה מה מותקן:

```bash
java -version
```

## הרצה

```bash
firebase emulators:exec --only database --project demo-shishi "node --test --test-concurrency=1 test/rules/"
```

הדגל `--test-concurrency=1` אינו קישוט: כל הבדיקות חולקות אמולטור אחד וקבוצת
חוקים אחת, והבדיקה האחרונה מחליפה את החוקים ומחזירה אותם. הרצה במקביל תיצור
מרוץ על המצב המשותף.

הקידומת `demo-` בשם הפרויקט מבטיחה שהאמולטור עובד לגמרי מנותק, בלי לגעת בשום
פרויקט אמיתי.

## מה נבדק

התרחיש שמוגדר ב-[../../DOCS/PLANING/09-database-permissions.md](../../DOCS/PLANING/09-database-permissions.md):

- משתמש ב׳ אינו יכול למשוך את רשימת כל האירועים, ואינו יכול למשוך את
  האירועים של משתמש א׳.
- משתמש א׳ **כן** מקבל את האירועים של עצמו — זו השאילתה שמסך המארגן מריץ,
  והיא הדבר היחיד שעלול להישבר מהשינוי.
- משתמש ב׳ פותח אירוע בודד לפי מזהה, מצטרף, וקורא — זרימת ההזמנה דרך קישור.
- מבקר שאינו מחובר אינו רואה דבר, כולל את רשימת המנהלים.
- הרשימות המוכנות הישנות נגישות לבעליהן בלבד.
- **בדיקת נסיגה:** מחזירה את חוק הקריאה הישן ומוכיחה שהדליפה הייתה אמיתית.

## שתי בדיקות שדורשות תשומת לב

**`sanity`** — מוודאת שהאמולטור באמת טוען את קובץ החוקים שלנו. אם שם המרחב
שגוי, האמולטור מגיש חוקים פתוחים לרווחה וכל שאר הבדיקות היו עוברות מהסיבה
הלא נכונה.

**`known gap: write access under events`** — בדיקה שמתעדת פער ידוע. היא
מוודאת שמשתמש ב׳ **כן** מצליח לכתוב לאירוע של א׳, כי כרגע זה המצב ואי אפשר
לתקן אותו בלי שינוי בקוד המוצר. ראה
[../../DOCS/PLANING/14-events-write-cascade.md](../../DOCS/PLANING/14-events-write-cascade.md).
**כשהפער ייסגר, הבדיקה הזו תיכשל** — וזה בכוונה. יש להפוך אותה אז לבדיקה
שמוודאת חסימה.

## למה הבדיקות משתמשות בספריית הלקוח ולא ב-REST

ההרשאות נבדקות דרך ספריית Firebase שהאפליקציה עצמה משתמשת בה. הסיבה מהותית:
הספרייה אינה משדרת "שווה לערך הזה" בפרוטוקול, אלא טווח שגבולותיו זהים. בדיקה
שהייתה מדברת REST הייתה עוברת בזמן שמסך המארגן נשבר בפועל.

הזרעת הנתונים לפני הבדיקות כן נעשית דרך REST עם הרשאת בעלים, כדי לעקוף את
החוקים בשלב ההכנה. זה מכוון.
