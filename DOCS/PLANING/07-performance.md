## למה זה חשוב לאפליקציה הזו במיוחד

זו אפליקציה שנפתחת מקישור שנשלח בוואטסאפ. תרחיש השימוש הטיפוסי: מישהו מקבל קישור לאירוע, לוחץ עליו בטלפון, ברשת סלולרית, ורוצה לראות מה להביא.

403KB ברשת סלולרית איטית זה המתנה מורגשת. וכל המשתמשים משלמים אותה — כולל מי שרק רוצה לראות רשימה ולשבץ את עצמו לפריט אחד.

הבעיה המרכזית: **הכל בקובץ אחד.** משתמש שנכנס לדף אירוע מוריד גם את כל קוד ניהול האירועים, את מודל הייבוא החכם, את עורך הקטגוריות, ואת ספריות ה-Excel — קוד שהוא לעולם לא יריץ.

## חשודים עיקריים

לפי התלויות ב-`package.json`, המועמדים לנתח הגדול ביותר:

| חבילה | הערכה | הערה |
|---|---|---|
| `firebase` | גדולה מאוד | נדרשת בכל מסלול |
| `xlsx` | גדולה מאוד | בשימוש רק בייבוא — מנהלים בלבד |
| `papaparse` | בינונית | בשימוש רק בייבוא |
| `lucide-react` | תלוי בייבוא | אם מיובאת נכון, רק האייקונים בשימוש נכנסים |

**לפני כל אופטימיזציה — למדוד.** בלי מדידה זה ניחוש:

```bash
npx vite-bundle-visualizer
```

## כיווני פעולה

### 1. פיצול לפי מסלול (ההשפעה הגדולה ביותר)

מסכי הניהול צריכים להיטען רק כשנכנסים אליהם:

```jsx
const EventForm = lazy(() => import('./components/Admin/EventForm'));
const ImportItemsModal = lazy(() => import('./components/Admin/ImportItemsModal'));
const BulkItemsManager = lazy(() => import('./components/Admin/BulkItemsManager'));
```

זה מוציא מהמסלול הראשי את כל קוד הניהול — שרוב המשתמשים לעולם לא נוגעים בו.

### 2. טעינה עצלה של `xlsx` ו-`papaparse`

הספריות הכבדות האלה נחוצות רק ברגע שמנהל בוחר קובץ לייבוא:

```js
const XLSX = await import('xlsx');
```

### 3. `manualChunks` להפרדת ספריות

הפרדת `firebase` ו-`react` לצ'אנק נפרד מאפשרת להם להישאר במטמון הדפדפן בין גרסאות — משתמש חוזר לא מוריד אותם שוב אחרי כל deploy.

## סדר מומלץ

1. למדוד עם `vite-bundle-visualizer` — לדעת מה באמת גדול
2. סעיף 1 (פיצול מסכי ניהול) — ההשפעה הגבוהה ביותר ביחס למאמץ
3. למדוד שוב
4. סעיפים 2–3 לפי מה שנשאר
