# 02 — חוקי מסד הנתונים לא נמצאים בבקרת גרסאות

> 🔴 **סיכון אבטחה והתאוששות. אין דדליין — ובדיוק בגלל זה זה נשכח.**

## הממצא

`firebase.json` מכיל היום רק:

```json
{
  "functions": {
    "source": "functions"
  }
}
```

אין בו סעיף `database`. ואין בפרויקט קובץ `database.rules.json`.

**המשמעות: חוקי האבטחה של Realtime Database קיימים אך ורק בקונסולה של Firebase.**

## למה זה מסוכן

האפליקציה מחזיקה נתוני משתמשים אמיתיים — שמות, מספרי טלפון (בהצעות טרמפים), ושיוך לאירועים. החוקים שמגנים על הנתונים האלה הם הדבר היחיד שעומד בין מסד הנתונים לבין האינטרנט הפתוח. וכרגע:

1. **אף אחד לא יכול לסקור אותם.** אי אפשר לעשות code review לחוקים שלא נמצאים בקוד.
2. **אין היסטוריה.** מי שינה אותם? מתי? למה? אין תשובה.
3. **אין גיבוי.** שינוי שגוי בקונסולה — אין ל־מה לחזור. אין `git revert`.
4. **אין תיעוד של הכוונה.** בעוד שנה אף אחד לא יזכור למה חוק מסוים נכתב כמו שנכתב.

זה בדיוק סוג הסיכון שלא מכאיב עד היום שהוא מכאיב מאוד.

## ⚠️ אזהרה קריטית לפני ביצוע

**אסור לכתוב את הקובץ הזה מאפס.**

חוקים שגויים ינתקו את כל המשתמשים מהאפליקציה באופן מיידי — או גרוע מכך, יפתחו את המסד לקריאה וכתיבה של כל אחד. חייבים **לייצא את החוקים הקיימים** ולוודא שהם עוברים כמו שהם.

תקדים בפרויקט: המיזוג של 23/08 הכיל `firestore.rules` עם התבנית הפתוחה לרווחה של Firebase (`allow read, write: if request.time < ...`) שגם פג תוקפה. הוא הוסר לפני שהזיק, אבל זה ממחיש בדיוק כמה קל להרוס כאן.

## מה לעשות

### שלב 1 — לייצא את החוקים הקיימים

בקונסולה: **Realtime Database → Rules**, ולהעתיק את התוכן **בדיוק כמו שהוא**.

לשמור אותו כ-`database.rules.json` בשורש הפרויקט.

### שלב 2 — לקמט לפני שמחברים ל-deploy

```bash
git add database.rules.json
git commit -m "chore: bring RTDB security rules under version control"
```

בשלב הזה הקובץ מתועד ומגובה, אבל עדיין **לא** מחובר לפריסה. זה כבר שווה משהו בפני עצמו.

### שלב 3 — לוודא התאמה מדויקת

לפני שמחברים ל-`firebase.json`, להשוות שורה־שורה מול הקונסולה. כל הבדל = סיכון לניתוק משתמשים.

### שלב 4 — לחבר לפריסה

ב-`firebase.json`:

```json
{
  "functions": {
    "source": "functions"
  },
  "database": {
    "rules": "database.rules.json"
  }
}
```

### שלב 5 — פריסה

```bash
firebase deploy --only database
```

## בדיקות אחרי פריסה

בדיקות בזמן אמת, ורצוי בשעה עם מעט משתמשים:

- [ ] משתמש רגיל רואה אירוע פעיל
- [ ] משתמש רגיל יכול לשבץ את עצמו לפריט
- [ ] משתמש רגיל יכול להוסיף פריט (באירוע שמאפשר)
- [ ] מנהל יכול לערוך אירוע
- [ ] משתמש **לא** מחובר לא רואה נתונים שאסור לו

אם משהו נשבר — לחזור מיד לחוקים הקודמים דרך הקונסולה.

## תוצאה

אחרי זה, כל שינוי בחוקי האבטחה עובר דרך גיט: ניתן לסקירה, לשחזור, ולתיעוד. וכמו כל שאר הקוד.
