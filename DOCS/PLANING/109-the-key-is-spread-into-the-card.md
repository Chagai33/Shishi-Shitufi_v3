# 109 — המפתח של כרטיס הפריט מועבר בפיזור, ו-React יפסיק לקבל אותו

> 🟡 **בינוני, ונפתחה 05/09/2026** אגב קמפיין [פרומפט 28](prompts/28-the-front-door.md),
> **מתוך אזהרה בקונסולה** שהופיעה בכל טעינה של עמוד אירוע.
>
> ⚠️ **לא תוקן במכוון**, כי אינו אחד משלושת הקומיטים של אותו קמפיין.

## מה קורה

`src/pages/EventPage.tsx:1084` בונה אובייקט מאפיינים שכולל בתוכו `key`:

```
key: item.id,
```

**ובשורה 1103 הוא מפוזר לתוך הרכיב:**

```
return isRide ? <RideCard {...commonProps} /> : <ItemCard {...commonProps} />;
```

**React מזהיר על זה בכל רינדור:**

> A props object containing a "key" prop is being spread into JSX

## מה עובד היום ומה יישבר

**היום זה עובד.** React 18 עדיין מוציא את `key` מתוך הפיזור, כותב אזהרה,
וממשיך.

**⚠️ ובגרסה הבאה זה מפסיק לעבוד.** `key` יגיע כמאפיין רגיל, והרשימה תישאר
בלי מפתחות בכלל.

**ומה שקורה לרשימה בלי מפתחות אינו קריסה, וזה החלק הלא נעים.** React מתאים
כרטיסים לפי מיקום במקום לפי זהות. **פריט שנמחק או שסודר מחדש גורם למצב
פנימי של כרטיס אחד לעבור לכרטיס אחר**, ובמסך הזה למצב הפנימי יש משמעות: איזה
כרטיס פתוח, מה נבחר בו, ואיזה חלון נפתח ממנו.

**כלומר התסמין יהיה כרטיס שמראה את הדבר של השכן שלו**, וזה סוג הבאג שקשה
מאוד לשחזר.

## התיקון

**להוציא את `key` מהאובייקט ולהעביר אותו ישירות**, כפי שהאזהרה עצמה אומרת:

```
<ItemCard key={item.id} {...commonProps} />
```

**שינוי של שורה אחת ופחות.** מה שמצדיק רשומה הוא לא הגודל, אלא **שהוא נראה
כמו ניקיון אזהרה והוא בעצם מונע באג עתידי במסך הליבה.**
