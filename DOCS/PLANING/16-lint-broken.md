# 16 — פקודת בדיקת התקינות של הקוד שבורה לגמרי

> 🟠 **סטטוס: פתוח.** נמצא ותועד ב-23/08/2026 בסוף קמפיין חוקי המסד.
> **לא תוקן במכוון** — התיקון הוא שדרוג תלות, וזה שייך ל-[03-dependencies.md](03-dependencies.md).
> רשומה חדשה בהתאם לכללים, לא תיקון אגבי.

## הבעיה בשפה עסקית

הפקודה שאמורה לבדוק את תקינות הקוד בפרויקט — `npm run lint` — **אינה עובדת
בכלל.** היא אינה מדווחת על בעיות בקוד ואינה מדווחת שהכול תקין; היא קורסת עם
שגיאה פנימית על **כל קובץ שהיא מנסה לבדוק**, כולל קבצים שאיש לא נגע בהם.

המשמעות: כלי בקרת האיכות היחיד שיש בפרויקט מלבד הקומפילציה **אינו נותן שום
כיסוי**, וכנראה כבר זמן מה.

## מה בדיוק קורה — אומת 23/08/2026

הכלי `eslint` בגרסה 9.31.0 אינו תואם לתוסף TypeScript שמותקן לצידו בגרסה 8.8.1.
התוסף מנסה להרחיב חוק פנימי של הכלי שהמבנה שלו השתנה, ונופל מיד:

```
TypeError: Error while loading rule '@typescript-eslint/no-unused-expressions':
Cannot read properties of undefined (reading 'allowShortCircuit')
```

**אומת שהתקלה אינה קשורה לקמפיין חוקי המסד:** אותה קריסה בדיוק מתרחשת גם על
`src/lib/firebase.ts`, קובץ שהקמפיין לא נגע בו.

## נקודה שראוי לשים לב אליה

ההרצה נופלת כשהיא מגיעה לקבצים בתיקייה `.agent`, שהיא תיקיית עזר מחוץ לבקרת
גרסאות ואינה חלק מקוד המוצר. גם אם התאימות תתוקן, כדאי להוסיף את התיקייה הזו
לרשימת ההתעלמות ב-`eslint.config.js` — כרגע מופיע שם `dist` בלבד. בלי זה,
הכלי יבדוק קוד לדוגמה של חבילות עזר ויציף בממצאים שאינם רלוונטיים.

## מה לעשות

1. ליישר את גרסת התוסף לגרסה שתואמת ל-ESLint 9. זה שדרוג תלות ולכן שייך
   ל-[03-dependencies.md](03-dependencies.md), ולא לתיקון נפרד.
2. להוסיף את `.agent` (ואת כל תיקיית ה-`temp`) לרשימת ההתעלמות.
3. להריץ בפעם הראשונה ולראות כמה ממצאים הצטברו בזמן שהכלי היה שבור. **לצפות
   לכמות גדולה** — הכלי לא נתן משוב תקופה לא ידועה.

## אימות אחרי מימוש

`npm run lint` מסתיים בלי קריסה ומדפיס רשימת ממצאים או הודעת ניקיון — כלומר
מגיע לסוף הריצה. זה תנאי הקבלה כולו; מספר הממצאים עצמו הוא שאלה נפרדת.
