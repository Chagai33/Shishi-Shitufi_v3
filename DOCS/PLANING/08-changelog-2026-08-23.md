## מה נמצא לפני המיזוג

### 1. קבצי Firestore מיותרים

מישהו הריץ `firebase init` ובחר בטעות Firestore. זה יצר `firestore.rules` ו-`firestore.indexes.json` וחיבר אותם ב-`firebase.json`.

**האפליקציה לא משתמשת ב-Firestore בכלל** — 0 קבצים מייבאים `firebase/firestore`, 7 מייבאים `firebase/database`.

החוקים שנוצרו היו התבנית הפתוחה לרווחה של Firebase, **שגם פג תוקפה ב-13/03/2026**. הסיכון לא היה לנתונים (הם ב-RTDB), אלא ש-`firebase deploy` היה מנסה לפרוס Firestore ועלול להיכשל — ולהפיל איתו את פריסת הפונקציות.

זה בדיוק מה שהתברר כקריטי בהמשך היום, כשנדרשה פריסת פונקציות דחופה.

→ `8bed39d`

### 2. קטגוריית טרמפים הייתה opt-out

```js
if (event.details.allowRideOffers !== false && ...)
```

בכל האירועים הקיימים השדה `undefined`, ו-`undefined !== false` הוא `true`. כלומר קטגוריית "הצעות טרמפ" הייתה מופיעה **בכל אירוע קיים בפרודקשן** ברגע ה-deploy.

שונה ל-`=== true` בשני מקומות (הקטגוריה והכפתור). הפיצ'ר נשאר זמין — `EventForm` מסמן את הטוגל כברירת מחדל לאירועים חדשים ושומר את השדה במפורש.

→ `b889671`

### 3. באג לוגיקת הקטגוריות

הקומיט `cbc36ad` מפברואר סומן במפורש: *"need to fix category logic"*. זה מה שהתברר:

```js
if (event.menuItems && ... && !areCategoriesEqual(formData.categories, event.details.categories || []))
```

אבל `formData.categories` מאותחל מ-`event?.details.categories || TEMPLATES['DEFAULT'].categories`.

באירוע legacy אין `details.categories`, ולכן ההשוואה הייתה תמיד **6 קטגוריות מול מערך ריק** — לעולם לא שווה.

**התוצאה:** כל מנהל שערך אירוע קיים עם פריטים — אפילו רק כדי לשנות שעה — נדחף למסלול "הגירה חכמה". והכפתור היחיד ששמר היה "הגירה חכמה". ההודעה הבטיחה *"ביטול: שמירה רגילה"* אבל ביטול רק סגר את החלון בלי לשמור.

תוקן בשניים: בסיס ההשוואה מיושר לאתחול הטופס, ונוסף כפתור "שמור בלי הגירה" אמיתי. הדיאלוג מציע עכשיו שלוש אפשרויות שכל אחת עושה מה שכתוב בה.

→ `e6f1979`

## מה נשבר אחרי המיזוג

### 4. מודל ה-AI הוצא משימוש

הייבוא החכם קרס עם "שגיאה פנימית בשרת". הלוגים גילו:

```
[404 Not Found] This model models/gemini-2.0-flash is no longer available.
Please update your code to use models/gemini-3.6-flash
```

**לא קשור למיזוג** — שורת המודל זהה בין הגרסה הישנה לחדשה. Google פשוט כיבתה את המודל איפשהו בחצי השנה שבה אף אחד לא נגע בפרויקט.

תוקן ל-`gemini-3.6-flash`, והוצא ל-`GEMINI_MODEL` כדי שההחלפה הבאה לא תדרוש עריכת קוד. בנוסף, 404 ממופה עכשיו ל-`unavailable` עם שם המודל בהודעה — במקום "שגיאה פנימית" גנרית שדרשה צלילה ללוגים.

→ `b9ad183`

### 5. פריסת הפונקציות נכשלה פעמיים

**כישלון ראשון:**
```
Couldn't find firebase-functions package in your source code
```
ל-`functions/` יש `package.json` נפרד. `node_modules` שם לא היה קיים כלל. הפתרון: `npm install` בתוך `functions/`.

תוך כדי, npm ניקה מה-lockfile רשומה שגויה — פרויקט האב נרשם בטעות כתלות `".."` עם `extraneous: true`, מה שגרר את כל תלויות הפרונטאנד לתוך lockfile של הפונקציות.

→ `c3d73f2`

**כישלון שני:**
```
User code failed to load. Cannot determine backend specification. Timeout after 10000.
```

`admin.database()` רץ ברמת המודול, בתוך חלון גילוי הפונקציות של 10 שניות. הוסב לטעינה עצלה — שני מקומות השימוש נמצאים בתוך handlers ממילא.

הפתרון המשלים שהכריע: הגדלת ה-timeout.

```powershell
$env:FUNCTIONS_DISCOVERY_TIMEOUT=60; firebase deploy --only functions
```

**זו הפקודה כפי שהורצה באותו יום, והיא נשארת כאן כדי שהתיעוד יישאר נכון.**
מ-26/08/2026 הפקודה נושאת גם `--project shishi-shitufimt`. **להעתיק מהלוח, לא
מכאן.**

→ `11931ac`
