## הקשר חשוב לפני שנבהלים

רוב הפגיעויות ב-`functions/` הן **תלויות עקיפות** שמגיעות דרך `firebase-admin@11` — גרסה ישנה יחסית. הן לא קוד שאתה כתבת ולא חבילות שבחרת ישירות.

`websocket-driver` למשל מגיע דרך שרשרת התלויות של `firebase-admin`, ולא נמצא בשימוש ישיר באף שורת קוד בפרויקט.

זה מוריד את הדחיפות, אבל לא מאפס אותה: קוד שרץ בענן עם גישה מלאה למסד הנתונים הוא לא מקום להשאיר בו פגיעויות קריטיות פתוחות.

## מה לעשות

### הדרך הנכונה — שדרוג המקור

רוב הבעיות ייעלמו מעצמן בשדרוג `firebase-admin` ו-`firebase-functions`. לכן:

**המשימה הזו כפופה ל-[04-firebase-sdk.md](04-firebase-sdk.md).** לעשות אותה **אחרי** שדרוג ה-SDK, ואז לבדוק מה נשאר.

### מה שאסור לעשות

```bash
npm audit fix --force   # ← לא!
```

הדגל `--force` מבצע שדרוגי גרסאות שוברים בלי לשאול. על פונקציות שרצות בפרודקשן עם משתמשים חיים זו דרך מצוינת להפוך בעיית אבטחה תיאורטית לתקלה מוחשית.

### מה שכן אפשר לנסות בבטחה

```bash
cd functions
npm audit fix
```

בלי `--force`, הפקודה מתקנת רק מה שלא דורש שינוי גרסה שובר. שווה להריץ ולראות כמה יורד.

**אחרי כל תיקון — לפרוס ולבדוק:**

```powershell
$env:FUNCTIONS_DISCOVERY_TIMEOUT=60; firebase deploy --only functions --project shishi-shitufimt
```

## סדר מומלץ

1. להריץ `npm audit` על הפרונטאנד ולעדכן את המסמך הזה
2. `npm audit fix` (בלי force) ב-`functions/` — לראות כמה יורד
3. לפרוס ולבדוק
4. לבצע את [01](01-node-runtime.md) ואז [04](04-firebase-sdk.md)
5. להריץ `npm audit` שוב — רוב הרשימה אמורה להתקצר משמעותית
6. לטפל ידנית במה שנשאר
