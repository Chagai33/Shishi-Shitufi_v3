## מה המארגן רואה

**המארגן, ורק הוא.** הלוח נפתח רק למי שנרשם, `src/App.tsx:169`, והמשתתף מגיע
מקישור בלי להירשם.

**אירוע שנקבע ליום שישי בשבע בערב.** המארגן פותח את הלוח בבוקר יום האירוע כדי
לראות מי נרשם למה. **הכרטיס דהוי, הפס שלו אפור במקום כתום, ובפינה תג שכתוב בו
"הסתיים".** האירוע יתחיל רק בעוד תשע שעות.

**זה מתחיל בשלוש לפנות בוקר בקיץ, בשתיים בחורף, ונמשך את כל יום האירוע.**

## ⚠️ והמסך סותר את עצמו

**זה הפגם החזק יותר, והוא לא היה בתיאור המקורי.**

**הכרטיס יושב מתחת ללשונית "אירועים פעילים", והלשונית סופרת נכון.** הקיבוץ
ללשוניות מחשב את יום הייחוס מרכיבי זמן מקומי, `src/pages/DashboardPage.tsx:270`
עד `:284`, **ויש שם אפילו הערה בקוד שמסבירה שזה נעשה כדי להימנע מהיסט UTC.**

```
src/pages/DashboardPage.tsx:287
event.details.date >= referenceDateStr
```

**כלומר בעשר בבוקר ביום האירוע, הכרטיס נמצא ב"אירועים פעילים" ואומר "הסתיים".**
שני החישובים יושבים באותו קובץ, בהפרש של מאתיים חמישים שורות, **ואחד מהם עושה
בדיוק את מה שהשני שכח.**

## הסיבה

```
src/pages/DashboardPage.tsx:33
const isPast = new Date(event.details.date) < new Date();
```

**מחרוזת תאריך ISO בלי שעה נקראת כחצות UTC.** נמדד בהרצה:
`new Date('2026-09-05')` הוא `2026-09-05T00:00:00.000Z`, **שהוא 03:00 בישראל**.
בחורף, `new Date('2026-01-16')` הוא 02:00 בישראל.

**והשוואה מול `new Date()`, שהוא הרגע המקומי, הופכת נכונה באותה שנייה.**

## מה התג יכול לומר

```
src/pages/DashboardPage.tsx:90
{isPast ? t('dashboard.eventCard.status.ended') : event.details.isActive ? ... }
```

**`isPast` גובר על הכל.** שלוש האפשרויות הן "הסתיים" `he.json:269`, "פעיל"
`he.json:267`, ו"לא פעיל" `he.json:268`.

## ⚠️ מה שהתג לא עושה, וזה מה שמוריד את הדחיפות

**`isPast` מופיע ארבע פעמים בקובץ ולא יותר**, וכולן תצוגה:

- `:33` ההגדרה.
- `:65` עד `:69` צבע המסגרת ו-`opacity-75`.
- `:86` עד `:89` צבעי התג.
- `:90` טקסט התג.

**הוא אינו חוסם את כפתור "מעבר לאירוע"**, `:163` עד `:171`, שאין בו `disabled`
ואין בו התייחסות ל-`isPast`. **הוא אינו ממיין, אינו מסנן, אינו מקבץ ללשוניות,
ואינו קובע את מסך הריק.** אלה נשענים על `referenceDateStr` ועל `isActive`.

**כלומר זה שקר יומי בלוח, ולא חסימה.**

## הפער מול המסך שכן קובע

**עמוד האירוע משתמש בחישוב אחר לגמרי**, `isEventFinished` ב-`dateUtils.ts:71`,
שמצרף תאריך ושעה בלי `Z` ולכן נקרא כזמן מקומי. **הלוח אינו מייבא אותו כלל.**

**ההפרש נמדד: עשרים ושתיים שעות.** התג מתהפך ב-03:00 ביום האירוע, והשער בעמוד
האירוע עדיין מחזיק אותו פתוח עד 01:00 בלילה שאחריו.

## ⚠️ והחישוב הנכון קיים בפרויקט, ומשמש רק קוד מת

`isEventPast` ב-`src/utils/dateUtils.ts:29` בונה את שני התאריכים מרכיבי זמן
מקומי, `:35` עד `:39`, **ולכן הוא חסין בדיוק לתקלה הזו.** המייבאים היחידים שלו
הם רכיבים שאינם מיובאים באף מקום.

**הקוד החי בלוח כתב לעצמו גרסה משלו, והיא השבורה.**

## התיקון

**שורה אחת בקובץ אחד:**

```
src/pages/DashboardPage.tsx:33
const isPast = isEventFinished(event.details.date, event.details.time);
```

בתוספת הייבוא מ-`../utils/dateUtils`. **שום דבר אחר ברכיב אינו משתנה**, כי אותו
בוליאני ממשיך להזין את אותו תג ואת אותו עיצוב, **רק שעכשיו הוא מסכים עם השער
ועם הלשונית שהכרטיס יושב בה.**

**ושני דברים שצריך לומר למי שמתקן:**

1. **`isEventFinished` נופלת בעצמה על קלט פגום.** אם `time` ריק, התוצאה היא
   `Invalid Date`, ההשוואה מחזירה שקר בשקט, **והתג יגיד "פעיל" לנצח.** זה
   ממצא שכבר רשום ב-[41](41-anonymous-data-never-expires.md), שם ב-`:137`,
   **ושם גם כתוב התיקון.**
2. **שש השעות עצמן פתוחות ב-[65](65-end-date-is-written-and-never-read.md)**,
   שרוצה שה-`endDate` שהמארגן כתב יקבע. **חיבור הלוח ל-`isEventFinished` נכון
   בשני התרחישים**, כי הוא מעביר את כל המסכים לחישוב אחד, ואז השינוי של 65
   מגיע ללוח בחינם.

## ⚠️ ומה שאסור לתקן כאן

**העותק הזהה של אותה שורה ב-`src/components/Admin/AdminEventsPanel.tsx:113`,
ואיתו התג ב-`:139` שמדפיס "הסתיים" כמחרוזת קשיחה בעברית מחוץ לקובצי התרגום.**

**לקובץ הזה אין מייבא**, ו-[06](06-dead-code.md) כבר מחזיקה אותו. **תיקון קוד
מת כאן רק יגרום ללוח הבקרה המת להיראות חי יותר ממה שהוא.**
